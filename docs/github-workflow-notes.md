# GitHub Workflow Notes

## Purpose

Use small, useful documentation changes to practice the complete GitHub flow without affecting production repositories.

## Baseline Workflow

1. Start from an up-to-date default branch.
2. Create a focused topic branch.
3. Make one understandable change.
4. Review the diff and validate formatting.
5. Open a pull request that explains the change.
6. Merge through the repository normal workflow.
7. Verify the merge and clean up the topic branch when appropriate.

## Safety Notes

- Never include credentials or private data.
- Never impersonate contributors or fabricate co-authorship.
- Keep exercises isolated from production repositories.
- Preserve issue, pull request, and commit links as workflow evidence.
